# 云构建后验证清单

> 适用：`HTFG_Kernel_Original` 的 **stock** 云构建产物。  
> 目的：每次刷机前确认四件事：① 产物来自正确的源码 pin；② `/proc/config.gz`/kheaders 与原厂一致；③ 内核里没有 KSU/SUSFS/KPM/root 痕迹；④ 合并后的 boot 只换了内核，ramdisk/头信息仍是原厂。  
> 一键检查：`python tools/check_artifact.py <zip> --boot <boot-new.img> --stock-boot 原厂镜像/boot.img`。  
> 本文分两部分：**A. 2026-11-07 本次验证记录**；**B. 以后每次构建的固定检查步骤**。

## B. 每次云构建后的固定检查

### B.0 准备

固定保留这些基线文件，不要随构建产物覆盖：

- `baseline/stock.config.gz`（原厂 `/proc/config.gz`）
- `baseline/stock_version.txt`（原厂 `/proc/version`）
- `原厂镜像/boot.img`（原厂 boot，用于对比 ramdisk/header）
- `manifest/pinned-sources.txt`（源码 pin）

同时保留**当前正在使用的、可正常开机的 boot 镜像**，作为回滚点。

### B.1 一键检查（必做）

```bash
cd G:/Trea_project/HT_Frame_Grab_Kernel_CC/HTFG_Kernel_Original
python -I tools/check_artifact.py \
  "云构建/<N>/HTFG_Image_oneplus_ace_race_v_stock_9-o-g38e2c85bc7af.zip" \
  --boot "云构建/<N>/boot-new.img" \
  --stock-boot "原厂镜像/boot.img"
```

期望最后一行：

```
RESULT: PASS (0 warning(s))
```

常见失败及含义：

| 失败行 | 含义 | 处理 |
|---|---|---|
| `Image sha256 ... does not match build-info` | zip 里的 Image 与 build-info 不是同一次产物 | 重新下载/重新构建，不要刷 |
| `kernel_source_sha ... does not match pin` | 构建用的源码不是 pin 的提交 | 检查 `Pin Kernel Source` 日志；更新/修复 pin |
| `Image embedded config differs ...` | 报告层不是原厂 config | 不要刷；检查 thermal 对齐或源码/config 变化 |
| `kheaders ... markers` | kheaders 里出现 root 关键词 | 不要刷；检查注入脚本/源码 |
| `boot kernel sha256 ... does not match artifact Image` | boot-new.img 不是用这个 artifact 的 Image 合并的 | 重新用紫罗兰合并 |
| `boot ramdisk differs ...` | 合并工具换了 ramdisk 或 boot 基座不对 | 用原厂 boot 作基座重新合并 |

**规则：任何 FAIL 都不允许通过改脚本/改断言绕过；先查清原因。**

### B.2 刷机前人工确认

- artifact 文件名包含 `_stock_` 和原厂后缀 `9-o-g38e2c85bc7af`（形如 `HTFG_Image_..._stock_...zip`）。
- `htfg-build-info.txt` 的 `kernel_source_sha` 与 `manifest/pinned-sources.txt` 一致（脚本已查）。
- 确认 `boot-new.img` 就是要刷的文件；不要混用旧构建的 boot-new。
- Image-only 产物**不能直接刷**：先用紫罗兰“制作 GKI 镜像”，内核选 `Image`、底包选原厂 `boot.img`，得到 `boot-new.img`。
- 如果紫罗兰不直接接受 zip，先把 `Image` 解压出来再选。
- 电量 > 50%；确认自己会进 fastboot/恢复模式；记录回滚用的 boot 镜像路径。

### B.3 刷机后设备检查（必做）

```bash
export MSYS_NO_PATHCONV=1
adb shell uname -r
adb exec-out cat /proc/version
adb shell 'zcat /proc/config.gz | sha256sum'
adb shell 'zcat /proc/config.gz | wc -l'
adb shell 'zcat /proc/config.gz | grep -cE "^(CONFIG_HTFG|CONFIG_KSU|CONFIG_SUSFS|CONFIG_KPM|CONFIG_BBG)"'
adb shell 'wc -l < /proc/modules'
adb shell 'grep -ciE "htfg|ksu|susfs|kpm" /proc/modules'
adb shell 'grep -ciE "htfg|ksu|susfs|kpm" /proc/net/unix'
```

期望：

| 命令 | 期望 |
|---|---|
| `uname -r` | `5.10.236-android12-9-o-g38e2c85bc7af` |
| `/proc/version` | 与 `baseline/stock_version.txt` 逐字一致 |
| config sha256 | `7d939635d77acbaa49a3e4ab2bdbb154c0a2c5e393b8057fa11a49071b56f149` |
| config 行数 | 8,276 |
| config 禁忌行 | `0` |
| `/proc/modules` | 522（本 ROM 基线；数量明显变化要查 vendor 模块加载） |
| modules/unix 关键词 | `0`、`0` |

然后做功能验收：

- App 的 UI 拉取能返回节点，字段正常；
- 触摸点击、长按、滑动正常；
- WiFi / 蓝牙 / 相机 / 热管理正常，无异常重启或明显发热；
- 观察一段时间（建议至少一轮日常使用）再删除上一版可回滚 boot。

说明：`dmesg`、`/proc/kallsyms`、`/sys/kernel/kheaders.tar.xz`、`/proc/cmdline` 在本 ROM 对 shell 不可读；不要为了检查它们去加 root 通道。构建期检查 + 源码零 printk 已经是这条线的证据。

### B.4 回滚

出现以下任一情况立即回滚到上一版可启动 boot（或原厂 boot）：

- 无法开机 / 卡 logo / 反复重启；
- vendor 模块大量加载失败（`/proc/modules` 数量明显下降）；
- WiFi/相机/热管理等核心功能异常；
- App 的 UI 拉取或触摸完全不可用，且确认不是客户端问题。

回滚后再保留当次 `HTFG Verify` 日志和 `check_artifact.py` 输出，定位是构建、合并还是刷机步骤的问题。

### B.5 记录

每次把以下信息补到本文件末尾（或单独的构建日志）：

- 日期、artifact 路径、repo commit、kernel source SHA；
- Image sha256、config sha256、boot-new.img 的 sha256；
- `check_artifact.py` 的 RESULT 行；
- 设备侧 `uname -r`、config sha、模块数、功能验收结论；
- 任何跳过项及原因（不能静默跳过）。

## C. 关于旧 AK3 zip 里的 `tools/magiskboot`、`tools/magiskpolicy`

**当前产物已经是 Image-only，不再包含任何 AnyKernel3 文件或 `tools/`。** 这一节只用于解释 2026-11-07 及以前的旧 zip。

旧 AK3 zip 里这两个文件的位置是 `tools/` 子目录，不在 zip 根目录：

```
tools/magiskboot      878652 bytes
tools/magiskpolicy    257624 bytes
```

它们是 AnyKernel3 模板自带的打包工具，用于 AK3 刷机脚本处理 boot 镜像；不在内核 Image 内，也不是内核里的 root 功能。紫罗兰合并路径只取 `Image`，不会执行它们。

如果解压旧 zip 后没看到它们，通常是：

1. 只看了 zip 根目录，没进 `tools/` 子目录；
2. Windows 杀毒软件在解压时把 Magisk 名字的工具隔离了（zip 文件本身仍然包含它们，可用 `unzip -l` 核对）。

核对旧 zip 的命令：

```bash
unzip -l "云构建/<N>/HTFG_Clean_....zip" | grep -i magisk
```

新产物 `HTFG_Image_...zip` 里只有 `Image`、`htfg-build-info.txt`、`SHA256SUMS`，没有这些工具。
